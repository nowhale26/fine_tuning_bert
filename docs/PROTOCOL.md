## Контроль реализации

Сохраняем авторский `mAdamW`, включая порядок weight decay и формулу epsilon/bias correction. Замена на современный `torch.optim.AdamW` без проверки не считается эквивалентной. В каждом режиме одинаковы данные, truncation, dropout, initialization std, precision, размер batch и частота оценки. При одинаковом seed в пределах одной архитектуры воспроизводим инициализацию и начальный порядок данных. Побитовую идентичность между устройствами не обещаем.

`run_pilot.py` меняет только выбор коротких выходных каталогов; обучение и checkpoint selection выполняет upstream. Оригинальный `early_stopping=true` сохраняет лучший dev checkpoint, но не задаёт patience-based остановку. В YAML A флаг false, в B true; это часть аудита публичной реализации. Не утверждаем, что доказали соответствие этих файлов точным историческим запускам Table 1.

Дополнительное сохранение last, экспорт predictions и диагностику градиентов реализуем до основной серии и внесём отдельным commit. Проверим на коротком техническом прогоне, что instrumentation не меняет градиенты, шаги optimizer, режим train/eval и состояние RNG. Текущий пилот с seed 0 не объявляем выполнением этой будущей instrumentation.

## Оценка и checkpoint

Accuracy = число правильных ответов / 277, по объединённым predictions полного dev. Последний неполный eval batch сохраняется; не усредняем batch accuracies без весов. На одинаковых шагах не учитываем дублирующиеся записи оценки как независимые наблюдения. Конечная оценка восстановленного checkpoint в upstream может иметь `global_step=-1`.

Для каждой траектории сохраняем last после всех шагов и best по dev accuracy, включая исходный checkpoint. При равных значениях best оставляем более ранний, соответствуя строгому `>` в upstream. Восстановленные веса оцениваем повторно, без dropout. Для Table 1 используем A-last/B-best; W2 дополнительно сравнивает A-last/B-last и чувствительность best-minus-last внутри каждого режима. Выбор лучшего по dev не даёт независимой test-оценки.

Итоговый full-train NLL считаем в eval mode как сумму отрицательных log-probabilities правильных классов, делённую на 2490. Это отдельная метрика; она не равна среднему логируемому training loss со включённым dropout. Константный majority predictor выбирает класс только по train и затем оценивается на dev.

## Диагностика градиентов

Для блока l норма `g_l(t)` — L2-норма конкатенации всех существующих gradients его параметров после backward, до clipping и optimizer.step. Отсутствующий gradient отмечаем отдельно; не подменяем его автоматически числом 0. Для classifier считаем аналогичную норму `g_head(t)`.

Для каждого run вычисляем `R = median_t[g_0(t) / max(g_head(t), 1e-12)]` по шагам t=1..100. Дополнительно сохраняем обе исходные нормы и число шагов с нулевым head gradient. Все режимы логируют первые 100 шагов и далее каждый 50-й. Large: блоки 0/11/23; base: 0/5/11.

Сравнение R для запусков с last full-train NLL ≥0.65 и остальных — описательная проверка ожидаемой связи. Если одна группа пуста или содержит один запуск, не заявляем устойчивую оценку группового разброса. Значения метрик на dev не служат критерием удаления запусков. Градиентная ассоциация не является доказательством причинности.

## Статистика и отсутствующие запуски

Все accuracy сначала переводим в проценты. Для каждого режима приводим seed-level таблицу, mean, sample std с ddof=1, max и долю неудачных по majority baseline запусков. Bootstrap ресэмплирует пары индексов сидов с возвращением, 10 000 выборок, seed 2026; интервалы — percentile 2.5/97.5. Для W1 используем A/B только на тех же сидах 1–10, для сопоставления масштабов отдельно показываем первые пять large-сидов.

Если std(A)=0, отношение std не определяем. Для bootstrap отмечаем число выборок с нулевым знаменателем; интервал по конечным значениям явно называем условным, не полным интервалом для отношения. Интервалы абляций и scaling описательные, подтверждающий приоритет у A/B. Отсутствие значимости на 5–10 сидах не приравниваем к отсутствию эффекта.

Инфраструктурные сбои повторяем с тем же seed/config, сохраняя traceback и время обеих попыток. Если восстановление невозможно, парный анализ выполняем по пересечению доступных сидов, отдельно приводим число и причины пропусков; не скрываем неудачную оптимизацию. Серии не останавливаем по направлению mean/std.
